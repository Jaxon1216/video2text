## 0.2.0（完成，2026-09-29）

按分类列出 v0.2.0 的实际交付与后续项目。详见 `CHANGELOG.md`。

### 界面

1. **导航和页面层级（完成）。** 独立的新建转写、任务、文字稿入口；保留详情 URL，批量提交进入任务列表，完成后跳转文字稿并提示保存成功。
2. **模型选择栏与本地扫描（完成）。** CLI / Web 共用模型目录，按引擎切换默认；启动时只读扫描模型文件，支持手动刷新。区分文件状态与依赖安装状态，云端不扫描，缺失的可下载模型仍可选并提示首次下载。新配置默认 faster-whisper large-v3-turbo，旧配置保留。
3. **下载前确认（完成）。** TXT / Markdown / SRT 点击后显示站内确认弹窗，支持取消、Esc 和焦点恢复；确认后才下载。
4. **历史标题复制原链接（完成）。** 悬停或键盘聚焦显示独立复制按钮，触屏直接显示；复制不触发跳转，本地文件不显示。

### 任务与进度

5. **任务启动后可以中断（延期）。** 后续为任务服务和 Web API 增加取消能力，覆盖排队任务及下载、抽音频、识别阶段，并在任务详情和列表提供操作。
6. **轮询反馈与日志降噪（完成）。** 断连保留进度并重试，404 与处理失败分开展示；任务列表保留失败记录。只过滤正常轮询 access log，保留阶段、失败与启动日志。

### 识别

7. **新增 Qwen3-ASR（延期）。** 作为新的本地识别引擎接入，评估 0.6B / 1.7B 模型的依赖、硬件要求和中英文识别效果，再纳入模型选择。
8. **同一链接换模型时复用已有音频（延期）。** 为下载后的音频建立基于平台视频 ID 的缓存；更换模型重新识别时跳过重复下载和抽音频，同时保留 B 站字幕优先行为。

## 待讨论：课程视频图文文字稿（待办，2026-11-03）

状态：已完成一个本地视频的可行性实验；尚未进入功能开发。下面的功能范围、实现方式和精度数字都是讨论草案，不代表已确认需求或已经通过验收。

### 已有实验与边界

- 来源：已下载的 Redis 课程 `BV1o4p568Etd`，约 74 分 50 秒，1920×1080。复用本地 MP4，没有新增视频下载或重新转写。
- 全片每 5 秒低分辨率采样一次，共 898 次；比较画面变化时排除底部动态字幕，得到 34 次切换，加上首帧导出 35 张截图。缩略图复核课件页码 01~35，保留章节封面。
- 35 张原尺寸截图合计约 5.8 MB；按原始 ASR 片段起始时间关联，保留全部 1804 个片段。HTML、Markdown 与原始片段正文一致，桌面和手机预览、图片打开、检索与打包已检查。
- 截图标题在实验中逐张查看画面后填写，**尚未验证自动标题生成**；当前方法检测的是画面变化，不理解画面的知识重要性。
- 每 5 秒采样意味着翻页起点仍有约 5 秒的定位范围；图片抽取时刻有记录，但不能据此宣称讲解与图片已逐句精确对应。
- 使用带时间戳的原始稿，保留识别错字；已有 Redis 校订稿没有时间戳，尚未与截图自动对齐。没有完整扫描总耗时数据，也没有其他视频类型的验证。
- 实验材料：[离线图文样稿](../data/exports/Redis-关键帧图文样稿/Redis-关键帧图文样稿.html)、[截图时间清单](../data/exports/Redis-关键帧图文样稿/关键帧清单.json)、[Markdown 与图片包](../data/exports/Redis-关键帧图文样稿.zip)。这些是本机导出材料，不是已集成的产品能力。

### 建议的第一版功能范围

暂以“复习课程时，能同时看到讲解和相关 PPT、代码、架构图”为目标；主要使用场景需要先讨论确认。

1. **按需生成图文稿。** 建议先在已有文字稿详情页提供生成入口，复用已保留的视频；作为独立步骤显示进度、允许取消和重试。是否增加新建转写时的“图文稿”选项留待确认。
2. **抽取有用画面。** 静态 PPT 优先按翻页保留代表画面；屏幕录制的代码变化单独评估。过滤重复画面、空白或转场，保留真正包含信息的深色课件和短暂章节封面。建议允许删除多余截图、指定时间补图，自动结果仍需可修正。
3. **关联正文与时间线。** 带时间戳原稿按截图时间关联讲解段落；没有时间戳的 Qwen3-ASR 稿、编辑稿和 AI 优化稿先提供独立截图时间线，不自动借用原稿 segments。校订稿的段落关联作为独立能力讨论。
4. **阅读与导出。** 网页在正文附近显示图片，支持看原图和跳转原视频时间；导出 Markdown＋图片 ZIP。TXT、SRT 保持各自用途；是否需要独立离线 HTML 导出待确认。
5. **版本与复用。** 同一视频的截图可共用；图片与正文的关联结果绑定具体文字稿版本。删除或重生成截图不覆盖文字稿；视频源变化时不能继续复用旧截图结果。

第一版建议聚焦课程画面与原稿关联；OCR、代码转成可复制文本、自动图注、语义选帧，以及将截图配到重写后的 AI 学习笔记，分别评估收益和工作量，不默认全部纳入。

### 建议的实现方式

- **先确认媒体可用。** 当前 `video_path` 字段也可能指向纯音频，必须用 ffprobe 检查是否存在可解码的视频轨道。缺少画面时，明确提示需要获取视频，再按用户选择下载含画面的媒体；字幕或 WAV 缓存命中不代表已有视频。
- **下载策略按用途区分。** 建议普通文字稿走字幕或音频优先，图文任务需要视频轨道并优先复用已有媒体。B站现有视频下载是否同时改为音频优先，作为相关但独立的取舍确认；不要让所有转写任务都额外下载视频。
- **分两步选帧。** 用低分辨率灰度图粗扫候选变化，屏蔽字幕和其他稳定的干扰区域；再在候选切换附近加密到 0.5~1 秒采样，选择画面稳定后的代表帧，按原尺寸输出。采样间隔、变化阈值和去重策略需要按 PPT、代码录屏分别验证，不能把 Redis 样本的参数直接当作通用标准。
- **截图记录与正文分开保存。** 每张图记录抽取时间、候选画面区间、文件路径、来源指纹与生成参数；关联记录引用视频、截图和文字稿版本。先沿用 SQLite＋本地文件，不引入额外服务。
- **遵守现有分层。** 平台下载器负责拿媒体；独立的抽帧模块负责“视频→截图与时间清单”，不塞进 ASR 引擎。任务编排复用现有任务服务、工作区锁和取消机制；library 管理资源与版本，Web 展示、formatters 负责导出。具体模块和接口在讨论定稿后再设计。
- **处理失败时保留已有结果。** 视频缺失、损坏、截图失败或用户取消，不能破坏已完成的转写和旧图文结果；图片完成后再登记，重试应能复用通过校验的结果。

### 精度与验收草案

以下是建议目标，**均未经过多样本验收**。画面选择、翻页定位、正文关联和图片清晰度分别评价，避免用一个“准确率”概括全部能力。

| 维度 | 建议目标 | 如何验证 |
| --- | --- | --- |
| 静态 PPT 覆盖 | 有信息的课件页覆盖率 ≥95%，重复截图占比 ≤5% | 人工标注应保留的页面，明确章节封面和转场是否计入；分别统计遗漏、重复与误选 |
| 翻页定位 | 95% 的检测切换点与人工标注相差 ≤2 秒 | 标注稳定新页面出现的时刻；粗扫后加密定位，单独测量，不沿用 5 秒采样结果冒充达标 |
| 截图清晰度 | 保留来源分辨率，不放大低清视频；原图中的关键代码和图中文字可辨认 | 对照原视频逐张检查代表页面，统计模糊、过渡画面和遮挡；1080p 是 Redis 样本规格，不是所有视频的固定输出 |
| 带时间戳原稿关联 | 首版按既有片段定位；暂建议 ≥90% 的抽检图片位于相关讲解段落附近 | 人工检查图片与讲解是否在同一知识点；跨翻页的口述片段允许引用相邻画面，另记 ASR 时间戳偏差 |
| 无时间戳或重写稿 | 首版不承诺自动段落对齐；时间线完整且时间顺序正确 | 检查版本切换与导出不误沿用原稿时间戳。若要自动对齐，需另定成功率、置信度和人工修正机制 |
| 导出完整性 | 图片引用全部可解析；时间顺序正确；正文无遗漏、重复或意外改写 | 检查本地相对路径与 ZIP；比对所选版本正文，验证 HTML / Markdown 资源与版本一致 |
| 性能与资源 | 暂不承诺固定耗时、截图数量和包大小 | 记录整段扫描＋定位＋导出总耗时、峰值内存、磁盘占用和图片数量，再根据本机课程长度确定上限 |

正式验收建议至少覆盖静态 PPT、代码录屏、含动画或字幕干扰的混合课程，各用一个完整样本；记录成功与失败。Redis 是其中一个候选样本，35 页均抽出只能证明这个课件的可行性，不代表所有课程都能自动选好关键帧。

### 讨论顺序与待定事项

1. **主要用途与文字版本：** 图文稿主要用于自己复习、交给 AI 整理，还是对外分享？优先关联原始稿还是校订 / AI 优化稿？
2. **首版视频范围：** 先支持静态 PPT，还是必须同时覆盖代码录屏？“关键”指每页内容都保留，还是只保留重点？
3. **用户操作与下载：** 从已有稿件按需生成是否足够？缺视频时怎样触发下载，视频和图片保留多久？
4. **可接受的错误与修正：** 漏掉一张重要代码图、重复几张截图、关联偏一个段落，哪种更影响使用？允许多少人工删图和补图？
5. **验收数字与优先级：** 上述 95% / 2 秒 / 90% 是否符合实际需求？确定资源预算和交付格式后，再收敛第一版及后续范围。

## 已知问题

- YouTube 重新下载同一视频时出现 `[SSL: UNEXPECTED_EOF_WHILE_READING]`，yt-dlp 重试后仍失败；尚未定位是代理、网络连接还是其他因素，稳定性待验证。
- 真实测试额外设置 `HF_HUB_OFFLINE=1` 后，faster-whisper 前两次无法找到可用模型缓存快照，后续同配置成功，原因待排查。磁盘上有模型文件不能作为运行可用的证据；此问题发生在本地模型加载阶段。
- openai-whisper 转写中文时经常输出繁体、没有标点；已改用 faster-whisper 为默认引擎，并在 `language=zh` 时自动加简体中文提示词。openai-whisper 保持原样。
- 专业术语（如“线程池”）容易识别错，通过 `--prompt` 传入术语可明显改善；阶段 7 评测时量化。
