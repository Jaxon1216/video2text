# 给课程文字稿配图：怎样生成，怎样测

2026-11-05。已确认用途是自己复习课程。文字稿是主产物，截图辅助阅读。在新建转写页，粘贴视频链接后可勾选“为文字稿配图”，默认关闭。点击“转成文字”提交同一个转写任务，由后端读取这次选择。希望读者遇到“看图里这条箭头”这样的讲解时，可以在正文旁看到原图。本文保留开发前的实验和备选指标；已交付的范围及 Redis 整链实测见[真实回归记录](good-cases.md#bilibili-redis-course)。[路线图](roadmap.md#已有实验与边界) · [术语表](../GLOSSARY.md)

## 从一个真实错配开始

Redis 样稿有 35 张图，1804 个原稿片段都按顺序保留。第 4 页“内存数据库”在 202.5 秒截到了图，但样稿按粗扫得到的 200–210 秒分组，给这一页分配了零个片段。讲这一页的第 16 号片段（从 0 编号）是 199.58–209.68 秒，整段被算进前页。局部按每秒 4 帧解码、比较课件区域与前后页截图，估计第 4 页在约 198.50–209.75 秒可见。这两个时刻是局部画面对比结果，统计全片精度还需要人工标注。[样稿时间清单](../data/exports/Redis-关键帧图文样稿/关键帧清单.json) · [真实案例](good-cases.md#bilibili-redis-course)

34 个粗切点里有 24 个落在原稿片段中间。保持这套粗区间，试算“归到重叠最长的一页”：第 16 号片段与第 3 页重叠 0.42 秒、与第 4 页重叠 9.68 秒，这条讲解就回到了正确的一页。全片有 13 段会换页，另外 2 个末尾片段与所有区间都无重叠。13 是发生变化的数量，其余换页的语义还需逐段核对。

第一组回归例可以取第 4 页、后段 Cluster 的跨页讲解、越过媒体时长的末句。一次检查图放在哪里，另一次将导出正文与所选稿逐段比对，避免为了对齐而裁掉或复制文字。

## 不用识图模型怎样截图

项目登记的五种引擎都是语音识别引擎，Qwen3-ASR 也只接收音频。[模型目录](../src/v2t/model_catalog.py) MVP 建议用已有的 FFmpeg 在选定时刻取一帧。下面的命令已在临时目录对 Redis 原视频运行，得到 1920×1080 JPEG；只需本地视频，不用重跑 ASR。

```bash
ffmpeg -ss 3807.5 -i data/downloads/BV1o4p568Etd.mp4 -map 0:V:0 -frames:v 1 -q:v 2 主从复制.jpg
```

采样和保存大图是两步。Redis 历史样稿每 5 秒比较一张 320×180 灰度小图，只看课件区域以避开动态字幕。清单记录的两个阈值是像素灰度差 24 和变化像素比例 2.5%；35 张原图的时间都是候选起点加 2.5 秒。举例说，在 0–255 的灰度范围内，可以统计与前一小图相差超过 24 的像素，在比较区域中所占的比例超过 2.5% 时记一个候选。该组参数来自这门课；短页、浅色背景只改一行、摄像头小窗都要单独复测。

本次用 FFmpeg 滤镜 `fps=1/5,scale=320:180:flags=area,format=gray` 重新顺序解码，在下述课件区域内比较相邻帧。首帧保留，之后仅在变化像素占比严格大于 2.5% 时保留。898 个样本复现了原清单中全部 35 个候选序号和记录的变化比例。单次低清解码及比较约 61 秒；历史清单的 3.18 秒仅是导出大图的用时。另可用 FFmpeg 的场景检测滤镜作对照，其场景分数与上述像素比例是不同指标。[FFmpeg scdet 文档](https://ffmpeg.org/ffmpeg-filters.html#scdet)

将这门 4490.585 秒的课程按 50 秒分窗，最后一个短窗也选一个时刻。音量、字密两种策略都把每个大窗再切成不重叠的 5 秒小窗，按小窗实际时长计算，选得分最高的小窗中点，并列则取最早。音量用 WAV 采样值的平均平方；字密以 ASR 片段的字母和数字（含汉字）按时间均匀分配估算。对每个选点用 FFmpeg 解码原视频，缩至 320×180 灰度，取 x=[6,314)、y=[9,158) 的课件区域，与 35 张参考图比较，选逐像素平均绝对差最小的一页。

| 选时刻的规则 | 选点数 | 实际视频帧匹配到的不同页数 |
| --- | ---: | ---: |
| 每窗起点，从 0 秒开始 | 90 | 30 / 35 |
| 每窗中央 | 90 | 30 / 35 |
| 每窗平均音频功率最高的 5 秒，取中点 | 90 | 29 / 35 |
| 每窗原稿字符最密的 5 秒，取中点 | 90 | 28 / 35 |

从 0 秒开始每 50 秒实际抽到 **30 个不同页，60 次落在已采页面**。例如第 15 页粗区间从 1800 秒起，但 1800 秒的实际帧还在第 14 页，仅查清单会多算一页。此次漏掉 11、15、20、23、28 页，都是章节引入页。第 4 页也说明声音触发可能错过短页：在 200–250 秒这一窗，200 秒时课件还显示“内存数据库”，最响的时刻 237.5 秒和字最密的时刻 242.5 秒都落到了下一页。覆盖计数只衡量拍到几个不同画面；关键页要另外人工标注。

按首版选定的 80 秒间隔，用相同方法重新解码 0 至 4480 秒的 57 帧，命中 29/35 页。相比 50 秒少取 33 帧，只额外漏掉第 4 页“内存数据库”；第 30 页“主从复制”和第 34 页“场景速查卡”均取到了。

## 第一轮实现建议

**首版输出采样截图。** 勾选配图后，每 80 秒取一帧：0、80、160 秒依次取到视频结尾之前。将相邻样本缩成灰度小图比较，近似相同时只保留一张。留下的截图带实际视频时间；有时间戳的文字稿可以就近展示，没有时间戳的版本按截图时间排列。用人工标注的关键页检验复习效果；如发现重要的短页经常被跳过，再对比每 5 秒粗扫的方案。

讨论中提到的“指图补截”最多能做成字面匹配：若有带时间戳的字幕或 ASR 片段，程序可以搜索“看这张图”等字串，命中后在该片段起点取一帧。匹配能定位这句话，却无法验证当时画面里是否有图、说话者指向哪里或这一帧是否值得留。首版不采用这种触发规则。

在 Redis 样稿上逐张查看了三个候选及附近原稿，作为标注示例：

- 第 28 页“持久化与高可用”只有章节标题和引题，建议跳过。
- 第 30 页“主从复制”画出一个主节点连到三个从节点，讲解也通过“上面”“下面”指图。建议保留一张。
- 第 34 页“场景速查卡”列出场景和具体命令，口述只展开其中一项。它以文字为主，复习时仍有独立价值，建议保留。以上是三个查阅示例，尚未运行自动筛选或取得人工盲评结果。

1. **把选择带进转写任务。** 建议使用布尔参数 `include_screenshots`，默认 `false`。新建页的单条与批量提交共用这一选项，每条任务保存自己的值，按原参数重试时沿用。先走已有的字幕、缓存或语音识别流程取得正文。只有开启时才为配图检查视频、获取所需画面、执行抽帧；可以先用本地 Redis 视频验通这一步。建议先登记可读文字稿，辅助步骤单独报告结果。详情页以正文为主，在相关段落附近显示截图。Markdown＋图片包和时间清单便于复测导出。
2. **分开记录采样时刻与翻页时刻。** 定时取样只能报告这帧出现在该时刻。可以在候选附近隔约 1 秒再查一帧，遇到转场取稳定后的帧。若要定位翻页，另用历史样稿的 5 秒粗扫加局部细扫作对照；5 秒内出现又消失的短页仍可能完全逃过粗扫。字幕遮罩仅用于比较，原图保留完整画面。
3. **截图可以共用，出现顺序要保留。** 画面由 A 切到 B 再回 A，阅读顺序有三段。人工复核时检查渐显、公式替换、代码运行前后三种情况，看定时采样是否留下了读者关心的状态。
4. **按时间展示采样截图。** 用截图的实际时刻找到对应的原稿片段；只有截图点时，不把它当成翻页起点。若后续获得更细的画面区间，可以再试按重叠时长关联。口述可能提前或滞后；原稿始终按原顺序展示一次。无时间戳的 Qwen、编辑或 AI 优化稿以独立时间线展示截图。使用项目现有的[按版本读稿](../src/v2t/services/library.py)。
5. **保留可复测的结果。** 时间清单记录来源、稿件版本、参数、区间、截图时刻、图片引用和讲解片段序号。验证临时产物后再发布，取消、解码失败或源文件更换时，已有稿件仍能打开。记录解码、取图和打包耗时、峰值内存及产物大小，供本机长课决定扫描频率。

## 验收方法

先看视频写答案，再看算法结果。人工标注每个应该保留的画面、稳定可读的起止时间、希望看清的细节、可接受的讲解段；单独记逐条渐显、回翻和无需配图的讲解。Redis 可调参，留一门来源或版式不同的完整静态 PPT 课作盲验，锁定参数后再跑。再用代码录屏、带动画或字幕的混合课程各一例找失效模式，按课程类型分别报结果。

| 要测什么 | 怎么计数或判定 |
| --- | --- |
| 默认转写 | 对同一输入模拟字幕命中和 WAV 命中。省略参数与显式关闭均正常产稿，对配图用的视频获取、探测、抽帧调用数均为零。 |
| 勾选配图 | 在模拟的单条和批量提交中，勾选值随任务传到解析流程；对可解码视频能看到配图和完整正文。建议另测缺视频或抽帧失败时正文可读、原参数重试仍选择配图。 |
| 漏图与多图 | 先对照原视频和正文独立标“必留 / 可选 / 可跳过”，再看算法。分别统计必留页有无清晰候选、最终命中多少必留页、插入多少可跳过页、多少重复图。可选页单列。A→B→A 保留最后一次出现的时间关联，正文可引用已有图片。用 Redis 的 35 页试标，再换一门课锁定标准盲测；两个阶段的遗漏分开记。 |
| 翻页时间 | 首画面计入覆盖，另测实际换页。人工与预测按同一翻页一对一匹配，每个点最多使用一次。以 ±2 秒为候选容差，同时报命中、漏检、误报原数，及已匹配切点的偏差。无换页的片段单记误报数。[一对一边界匹配的参考方法](https://mir-eval.readthedocs.io/latest/api/segment.html#mir_eval.segment.detection) |
| 能否复习 | 在同一份文字稿上对比纯文字阅读与开启配图的阅读。预先写一道只读讲解即可答的问题，再写一道需要看图的问题，例如“讲到 Cluster 时，图里哪些节点互相通信？”记录回答耗时、是否需要回看视频，以及配图是否打断连续阅读。选帧算法再与等量的等间隔截图对照。 |
| 导出完整性 | 按原序逐段比对正文，每段恰好一次；解压到新目录后逐一检查相对图片链接。用合成短视频或片段测试短页、回翻、深色课件、动态字幕、无画面、取消、无时间戳和结尾越界。自动测试离线，真实课程手动复测。 |

调研草案中的页覆盖 ≥95%、重复 ≤5%、95% 的翻页误差 ≤2 秒、抽检图文相关 ≥90% 都是候选目标。先报告原数，比如 35 页中漏 1 页，并展示漏掉哪一页、是否影响复习；盲验后再定门槛。当前只核查了 Redis 已有产物与视频局部，第二门课、阅读对照和完整扫描耗时仍待实测。
