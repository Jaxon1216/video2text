# 决策记录

每条记录：背景 / 决定 / 原因。新决策追加在末尾。

## D1 纯自用开发，不回馈 upstream

- 背景：项目 fork 自 [lanbinleo/bili2text](https://github.com/lanbinleo/bili2text)（MIT）。
- 决定：不再给 upstream 提 PR，`main` 是自己的主线；`upstream` remote 只作参考。
- 原因：自用需求（抖音、Copy for AI、React 前端）和原项目定位不同，兼顾 PR 会显著增加拆分成本。

## D2 抖音解析用 Playwright 浏览器截获

- 背景：2026-09 实测，抖音短链与分享页返回 WAF 人机校验页，纯 HTTP 拿不到数据；yt-dlp 抖音提取器长期损坏（yt-dlp#9667）；分享页 `_ROUTER_DATA` 已不含视频信息。真实浏览器可自动通过校验，页面会请求 `/aweme/v1/web/aweme/detail/` 并加载独立音频流；音频地址带 `Referer` 可脱离浏览器下载。
- 决定：用 Playwright 打开视频页，截获详情接口 JSON 拿元数据和音频地址，再用普通 HTTP 下载。不逆向 `a_bogus` 签名。
- 原因：单条公开视频、低频、自用；不依赖签名算法和 Cookie 池，抖音改算法时最不容易坏。代价是每条多几秒、需要安装浏览器。若以后嫌慢，可引入 jiji262/douyin-downloader（MIT）的签名实现作为快速路径。

## D3 保持 SQLite + 线程池

- 决定：不引入 Redis、消息队列、Postgres。
- 原因：本地单用户，任务量小；现有 SQLite + ThreadPoolExecutor 已能提供任务、进度和历史。

## D4 全面改名

- 决定：包名 `b2t` -> `v2t`，命令 `bili2text` -> `video2text`，工作目录 `.b2t` -> `.v2t`，环境变量 `B2T_*` -> `V2T_*`。旧 `.b2t` 数据作为测试数据丢弃，不做迁移。
- 原因：不再同步 upstream，没有保留原名的必要。LICENSE 按 MIT 要求保留原作者版权声明。

## D5 Web 前端改为 React SPA

- 决定：`web/` 下 Vite + React + TypeScript，构建产物由 FastAPI 托管（单进程）。SPA 跑通后删除 Jinja 页面。
- 原因：现有 JSON API 已比较完整；SPA 更方便做 Copy for AI、时间戳跳转等交互。

## D6 默认本地引擎改为 faster-whisper

- 背景：openai-whisper 依赖 torch、体积大；中文输出常为繁体且无标点；每个任务都会重新加载模型。
- 决定：新增 faster-whisper（CTranslate2，CPU 用 int8、开启 VAD）并设为默认；`language=zh` 时自动加简体中文提示词，用户 prompt 追加在后；factory 按配置缓存 transcriber；任务并发默认 1（`V2T_TASK_WORKERS`）。
- 原因：不需要 torch，Docker 镜像更小；实测 5 分钟抖音视频输出简体带标点，加术语 prompt 后专业词识别正确。

## D7 B站字幕优先，ASR 兜底

- 背景：B站很多技术视频有 CC 或 AI 字幕，直接用比 ASR 快得多、通常更准；但字幕需要登录 Cookie。
- 决定：`Downloader` 增加可选的 `fetch_subtitles`，pipeline 先取字幕，拿不到或出错就照常下载 + ASR。Cookie 支持 cookies.txt 与 `V2T_COOKIES_FROM_BROWSER`。
- 原因：不改变没有 Cookie 时的行为，只在条件满足时加速；抖音没有可用字幕，保持 ASR。

## D8 Docker 镜像只依赖一个基础镜像

- 背景：本机网络下 Docker Hub、ghcr.io 拉取超时，`deb.debian.org` 不稳定；PyPI 与 Playwright CDN 可用。
- 决定：前端构建和运行时都基于 `python:3.12-slim`（前端用 apt 装 Node 20）；uv 通过 pip 安装；不写 `# syntax=`；`APT_MIRROR` / `PIP_INDEX_URL` / `PLAYWRIGHT_DOWNLOAD_HOST` 作为可选构建参数；镜像不含 openai-whisper（torch）。
- 原因：网络受限时只要本地有一个基础镜像就能构建；镜像体积可控。

## D9 v0.2.0 先完成体验与现有模型管理

- 决定：本轮拆分新建转写、任务、文字稿页面，完善交互、轮询和模型选择。Qwen 接入、任务中断、音频复用延期。
- 默认策略：新配置默认 faster-whisper large-v3-turbo；已有配置不迁移，旧文件缺字段沿用 small。其他引擎独立解析默认值，显式模型名/路径优先。
- 原因：先降低现有流程的使用成本；新引擎与运行中中断需独立验证，避免扩大这一版本的技术风险。

## D10 模型扫描只报告文件状态

- 决定：启动与手动刷新只读检查缓存引用和关键文件；不下载、不导入 ML 引擎、不加载权重，依赖安装状态单独报告。文件已找到不代表能运行。
- 原因：启动开销可控，避免误触发下载或占用大块内存。缺失的可下载模型沿用首次转写下载流程，暂不做独立下载管理。

## D11 任务中断采用协作式检查

- 决定：保留线程池，排队任务取消 Future，运行任务通过取消令牌在处理检查点停止；不为每个任务启动独立工作进程。
- 原因：保持模型实例复用和现有任务架构。模型或网络库的不可中断调用可能继续运行到返回，但其结果不会登记为文字稿。

## D12 完整音频按来源缓存，重识别独立保存

- 决定：远程来源只缓存经格式校验的完整 16k 单声道 PCM WAV；B站按 BV 与分 P、抖音按视频 ID 区分，并记录原链接别名。写入使用临时文件和原子替换；旧文字稿音频在核对来源后导入。换模型重识别强制 ASR，结果生成独立文字稿。
- 原因：模型切换不必重复下载和抽音频；不同模型结果可直接对照，同时保持已有字幕优先流程和编辑版本结构。

## D13 Qwen3-ASR 先接 0.6B 纯文本

- 决定：使用官方 `qwen-asr==0.0.6`，仅开放 `Qwen/Qwen3-ASR-0.6B`；优先 Apple MPS，遇到 MPS 不兼容再试 CPU。术语提示传 `context`，中文模式输出纯文本和空 `segments`；没有时间戳时禁用 SRT。1.7B 与 ForcedAligner 暂不接入。
- 原因：M1 16 GB 本机实测可完成真实中文视频音频识别，进程峰值内存约 2.33 GB。当前 pyenv 的 Python 缺 `_lzma`，直接让官方包读音频路径会报错；改为用标准库/ffmpeg 解码并把 16k 样本数组传给官方接口。

## D14 Qwen3-ASR 改用 1.7B 并放宽输出长度

- 背景：用户实际使用 0.6B 的识别效果差。两版对同一段约 195 秒中文视频的初次转写都在半句话处结束；官方 `qwen-asr==0.0.6` 的 Transformers 后端默认只生成 512 个新 token，而该音频没有被分块。
- 决定：模型目录仅提供 1.7B；旧 0.6B 文字稿保留，旧默认配置在读取时转为 1.7B；每 60 秒音频调用一次官方识别接口，并将单段 `max_new_tokens` 设为 2048，在段间检查取消。仍采用 MPS 优先、CPU 回退、纯文本无时间戳方案。
- 原因：1.7B 满足更高模型规格的需求；只换权重或只把上限从 512 调到 2048，同一段视频仍被截断。较短音频分段能持续处理长视频，也让运行中取消有更多检查点。此调整尚不能替代人工校对的准确率评测。

## D15 SQLite 结构升级使用版本号

- 背景：原有建表和一次性补列逻辑都写在 `database.py` 的初始化方法里；后续新增字段会让升级路径难以核对。
- 决定：把 DDL 和升级步骤放到 `migrations.py`，用 SQLite `PRAGMA user_version` 标记版本。未标版本的旧库升级到版本 1，已有数据保留；程序拒绝打开版本更高的数据库。继续使用标准库 `sqlite3`，不引入迁移框架。
- 原因：满足本地单用户项目的数据演进需求，并把结构变更集中到一个可测试的入口。

## D16 YouTube 使用独立字幕库与 yt-dlp 音频回退

- 决定：新增 `YouTubeDownloader`，以 `youtube-transcript-api` 获取人工/自动原始字幕；无有效字幕或请求失败由既有 Pipeline 回退 `yt-dlp bestaudio/best`。不使用需要视频编辑权限的官方字幕下载 API，不引入额外字幕回退链、代理池或账号池。B站下载器保留原结构，只共享 Cookie、进度和下载路径辅助函数。
- 决定：字幕库和 yt-dlp 的 `default,deno` extras 作为基础依赖，uv 同步 EJS 与 Deno，避免本机或 Docker 缺少 JS 运行时。YouTube 默认使用系统代理；B站保持默认直连。Cookie 仅传入 yt-dlp，字幕库不读取浏览器登录态。
- 边界：只处理完整单视频；拒绝尚未结束或尚未处理完的直播。视频 ID 作为缓存标识；字幕标题/作者通过短超时 oEmbed 尽力补齐，失败不丢弃字幕，时长不从最后字幕时间推测。
- 原因：复用既有任务、缓存、导出和重转写，保持平台逻辑停留在 Downloader；优先交付可离线回归的自用 MVP，不承诺公共服务的反爬稳定性。

## D17 一个工作区只运行一个任务服务，重试复用持久化参数

- 背景：CLI 与 Web 都会创建任务服务，启动恢复曾把其他进程仍在执行的任务误标为失败；前端重试重新拼接普通任务请求，会丢失术语提示和重转写的强制 ASR 设置。
- 决定：任务服务先获取工作区进程排他锁，再恢复遗留任务；重复启动明确报错，允许通过不同工作区独立运行。正常关闭等待任务结束后释放锁，进程退出由操作系统释放锁。SQLite 升级到版本 2，保存 `prompt` 与有效的 `force_asr`，后端按原参数创建重试任务；旧任务缺失的选项使用默认值。
- 原因：保持 SQLite + 线程池和单进程 Web 部署，不新增任务代理、端口发现或心跳机制；重试的识别行为由后端统一保证。

## D18 AI 优化稿使用固定交付文件与独立版本

- 背景：外部 AI 润色后的文件曾放在 `exports/`，详情页仍读取原稿及 metadata 分段；直接替换原始 txt 无法让时间戳正文同步变化。
- 决定：约定 `<工作区>/transcripts/ai/video-{视频ID}.txt` 为 UTF-8 纯文本交付文件，Copy for AI 提供后端绝对路径。查询版本列表时同步文件，按最新 AI 版本内容哈希去重，为每次变化另存独立快照并登记 `ai_optimized`，不修改原稿或 active 指针；不引入文件监控或内置 AI 服务。
- 决定：详情页提供原始稿 / AI 优化 tab，复制和 Web 导出显式传所选版本；优化稿不借用原稿时间戳，禁用 SRT。无交付稿或文件无效时显示保存路径或错误，历史版本继续保留。
- 原因：适合个人在本地 AI 编程助手中润色并落盘的流程，复用现有文件存储和版本索引，保留原始识别结果供对照。

## D19 文件命名复用视频标题

- 背景：原始稿的微秒时间及随机后缀过长，AI 交付文件只有数字 ID；网页导出不同稿件类型时使用相同文件名，难以辨认内容及版本。
- 决定：复用平台解析得到的标题，本地来源用文件名，缺标题沿用来源标识，不增加正文主题分析、AI 调用或命名配置。文件名中的标题保留中文、清理非法字符并截到 60 字符，原稿使用 `标题-原始稿-YYYY-MM-DD_HHMMSS.txt`，AI 交付文件使用 `标题-AI优化-视频ID.txt`，CLI / Web 导出统一使用 `标题-稿件类型-视频ID.扩展名`。
- 决定：默认原稿、编辑稿及 AI 历史快照用排他创建，同名追加序号，不覆盖已有结果；显式输出路径继续按用户设置写入。已有原稿及快照不迁移，新 AI 交付文件不存在时兼容旧 `video-{视频ID}.txt`，新文件存在后优先新文件。
- 原因：用已有元数据改善辨识度，保留并发写入与历史稿件的正确性，无需数据库迁移或额外服务。

## D20 源码按入口、服务和存储归并

- 背景：CLI / Web、任务与文字稿服务、SQLite 与缓存模块都平铺在 `src/v2t/`，目录不能直接表达已存在的职责边界。
- 决定：将 CLI、Web、首次配置和 CLI 进度放入 `entrypoints/`；任务、pipeline 和 library 放入 `services/`；数据库、迁移、音频缓存和工作区锁放入 `storage/`。现有下载器与转写器目录保留，共享数据类、配置、工厂和纯函数继续放在包根目录。
- 决定：内部导入和测试使用新路径，安装入口改为 `v2t.entrypoints.cli:main`，同步调整 Web 对仓库 `web/dist` 的定位。仅移动源码，不新增包装层；CLI 命令、Web API、工作区数据路径及 SQLite 结构沿用现状。
- 原因：用少量目录表达现有结构，后续增加服务时有明确位置。Agent、抽帧和新的产物目录在功能进入开发时再按实际需求设计。


## D21 文字稿配图使用固定间隔，正文先交付

- 场景：自己复习课程时主要读文字，偶尔需要看当时的画面。项目配置的是语音识别模型。
- 决定：默认不取图；开启时每 80 秒取一帧并去除相邻近似画面。此规则不依赖声音强弱、文字关键词或视觉模型，因而对静音段与无时间戳稿件也可用。采样间隙内短暂出现的课件页可能完全漏掉。
- 正文与截图分别发布。固定采样时间只表示当时的画面，不代表翻页时刻；仅原稿可以按时间就近放图，编辑稿与 AI 优化稿保留独立时间线。选图失败或取消时仍能读正文，配图重试不再次运行 ASR。
